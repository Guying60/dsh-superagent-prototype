### 第 2 页：行业痛点与背景（Pain Points）

- **幻灯片视觉设计**：三栏对比卡片布局，使用醒目的警示红与对比灰。图解当前 Multi-Agent 框架落地中的三座大山，并配以“幻觉雪崩”恶性传播流程图。
- **核心板块**：
  1. **编排能力薄弱**：硬编码脚本流水线、缺乏声明式 DAG、无分支/回滚机制；
  2. **调度策略单一**：朴素顺序执行、无视 Agent 负载与专长画像、缺失自我循环迭代能力；
  3. **验证机制缺位**：中间产物未经核验直接流转、错误雪崩式放大、频繁向人弹窗产生“警报疲劳”。
- **【演讲稿 / 90 秒】**：
  > 业界目前并不缺少像 LangChain 这样基于 API 简单封装的框架，但当它们走进真实软件工程、科学计算或智能投研等严苛场景时，普遍撞上了“三面高墙”：  
  > 首先是**编排能力脆弱**，绝大多数框架依赖 Python/TS 过程式硬编码，遇到条件分支、并行同步和异常回退时捉襟见肘；  
  > 其次是**调度策略原始**，调度器对智能体的专长深度、瞬时并发负载毫无感知，完全缺失应对错误结果的自我循环与优化能力；  
  > 最致命的是**验证机制的缺失**。上一节点生成的代码或数据存在幻觉，未经验证就被塞给下一节点，错误像滚雪球一样扩散，最终只能靠频繁打扰人类工程师来收拾残局。这完全背离了 AI 辅助研发的初衷。

### 第 3 页：核心理念：基于 DSH 的注意力经济学（Philosophy）

- **幻灯片视觉设计**：天平图解。天平左侧是“人类精力消耗（零打扰/静默）”，天平右侧是“交付物确定性价值（高质量代码/补丁）”。四大铁律以高亮徽章形式罗列。
- **核心板块**：
  - **静默自治（Quiet Autonomy）**：严控消息噪音，中间过程内部自愈，只报告可交付成果；
  - **闭环自愈（Self-Loop Healing）**：将错误拦截在系统内，通过 PDCA 反思循环自主收敛；
  - **结构化升级（Structured Escalation）**：唯有在自愈穷尽或面临破坏性风险时，才弹出单问题交互卡片；
  - **零假设可信（Zero-Trust Verification）**：拒绝大模型盲信，所有输出必须通过确定性沙箱断言与红蓝交叉审计。
- **【演讲稿 / 80 秒】**：
  > 针对上述顽疾，我们的解法深深植根于 DeepSeek Harness 的原生哲学。在企业级多智能体系统中，**人类研发者的注意力才是最昂贵的硬通货**。  
  > 我们提出了四大工程铁律：系统在运行中保持静默自治，决不刷屏汇报“我正在思考”；我们将测试失败与语法漏洞作为反馈信号，通过内部的自我循环进行自愈；当多次尝试仍无法收敛时，系统以极简的结构化卡片请示人类，给出单明确问题和推荐动作；最后，对任何 LLM 产物坚持“零假设可信”，通过沙箱测试与多 Agent 红蓝对抗筑牢安全底线。

### 第 8 页：智能调度引擎：动态老化与负载均衡（Scheduler）

- **幻灯片视觉设计**：左右两幅算法原理图。左侧展示优先级随时间推移的老化阶梯函数曲线；右侧展示智能体能力评分与当前并发负载的加权分派热力图。
- **核心板块**：
  - **动态优先级老化算法**：$P_{effective} = \min(10, P_{base} + \lfloor \Delta t / \tau \rfloor)$，彻底杜绝任务饥饿；
  - **能力-负荷复合评分派发**：$S(A_j, k) = 0.7 \cdot Capability + 0.3 \cdot (1 - Load/MaxLoad)$；
  - 自动规避超载节点，实现全局吞吐量最大化。
- **【演讲稿 / 80 秒】**：
  > 调度是平台的神经中枢。如果只按静态优先级调度，队列中低优先级但关键的任务将被无限期饿死。  
  > 我们设计了**动态优先级老化算法**，任务在队列中每等待一个老化周期，其有效优先级便线性递增，保证了整体公平性。同时，调度引擎在派发时，综合加权考量 Agent 的专业匹配度和当前认知载荷，让最擅长且最空闲的智能体去接单，有效避免了单点过载造成的任务排队延迟。

### 第 9 页：核心创新：Self-Loop 自我循环状态机（The Self-Loop Engine）

- **幻灯片视觉设计**：高亮展示 PDCA（Plan-Do-Check-Act）循环闭环图。不同状态用发光节点标注，重点放大“Critic 根因反思”与“动态 Prompt 注入”的交互节点。
- **核心板块**：
  - **DO 阶段**：开发者生成初始实现；
  - **CHECK 阶段**：沙箱执行测试与多维交叉审计；
  - **ACT 阶段**：Critic 提取错误栈进行因果推断，制定结构化修改方案；
  - **PLAN 阶段**：注入诊断上下文，自适应调整 Prompt 并启动重试；
  - **有限终止性证明**：严苛的最大回退轮次与单调递减预算，保证有限步内必停机。
- **【演讲稿 / 100 秒】**：
  > **现在请各位评委聚焦本平台最核心的技术创新——Self-Loop 自我循环自愈引擎。**  
  > 传统系统一旦生成的代码跑不通测试，流程就直接挂掉或者疯狂给人类报警。而在 DSH-Orchestrator 中，我们实现了完整的 PDCA 反思闭环！  
  > 当沙箱测试报错时，CHECK 阶段捕获失败日志；ACT 阶段唤醒专职批评智能体 Marcus，对错误原因展开深度剖析，输出精准的修改对策；PLAN 阶段将对策动态注入给开发智能体进行定向修补。同时，我们通过数学上的良基关系保证了有限终止性，设定硬性收敛预算，既能自愈缺陷，又绝不陷入死循环。

### 第 10 页：多层结果验证流水线（Multi-Tier Verification）

- **核心板块**：

  - **Tier-2 隔离沙箱动态测试**（权重 40%）：自动化单元测试真实断言比对；
  - **Tier-3 多智能体交叉核验**（权重 30%）：Code Reviewer 与 Security Auditor 独立共识打分；
  - **综合得分阈值网关**：$\ge 90\%$ 且零致命漏洞方可放行。
- **【演讲稿 / 80 秒】**：
  > 如何保证多 Agent 输出的绝对可信？我们构筑了三层立体防御流水线：  
  > 第一层是耗时极低的确定性静态规则，拦截低级语法错误与安全违规；  
  > 第二层是将代码真正放入受控隔离沙箱，运行由验收规约生成的全套测试用例，用铁的事实验证算法逻辑；  
  > 第三层是红蓝交叉审查，由独立的代码评审员和安全审计员进行共识投票。三层加权得分必须突破 90 分大关，产物才被系统认可。
